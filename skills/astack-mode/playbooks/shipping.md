### Shipping

**You own what lands. Verify each PR independently, land only the verified run from the root, then keep your hands off the stack.**

1. **Verify each PR independently before it lands.** Use GitHub CLI (`gh`) and/or `github-mcp-server`. Run [`/review-pr`](../../review-pr/SKILL.md) (`node skills/review-pr/scripts/pr-dossier.mjs`) to confirm Risk Tier (`0..3`), `evidence.json` SHA freshness, and base-branch `REVIEW.md` compliance. Spawn an independent `@verifier` (using `agents/pr-verifier.md` or `/swarm` across distinct healthy model families via `swarm{action: "models", all: true}`) to exercise the change end-to-end as a user would through `control-ui` or `control-cli` (or `.agents/skills/verify-<app>/`), parent against head, and post `PASS`, `PASS+NOTES`, or `FAIL` on the PR. Green CI and bot approvals are inputs, not proof. Automated merge without an explicit human merge approval is allowed only when `.agents/risk-policy.json` sets `allowTier0AutoMerge: true` and `humanGates.prReview: "tier0-auto"` AND `evidence.json` reports `autoMergeEligible: true`; Tier 1 through Tier 3 PRs always require human review and approval.
2. **Land only the contiguous verified run rooted at the bottom.** Walk up from the lowest unmerged PR and stop at the first one without `PASS` or `PASS+NOTES`. The PRs below it are the run, and the top one is the ceiling. An independent PR above an unverified one must first move onto trunk and earn a fresh verdict on trunk.
3. **Re-check that verdicts still describe the code.** Compare `git patch-id` at the verdict SHA with the current head after chain rebases. Only test/doc/lint-config-only noise with identical build output may carry over; behavioral changes and live UI/server paths re-run verification.
4. **Land bottom-up, one PR at a time.** Always merge the lowest unmerged PR (`gh pr merge <pr> --squash --subject "<title>" --body "<concise summary>"` or repo default "Pull request title", or `github-mcp-server` `merge_pull_request`) so Mermaid statecharts and proof tables stay on GitHub without cluttering `git log`, then read the PR back (`gh pr view <pr> --json state,mergedAt,baseRefName`) to confirm actual merge rather than merge-queue enqueueing. Only arm `--auto` when the verdict covers that exact head. After each merge, retarget the child PR to trunk (`gh pr edit <pr> --base <trunk>`), rebase onto trunk, push `--force-with-lease`, check `git patch-id`, and merge once green.
5. **Leave the stack alone while it lands.** Watch the queued run with `node skills/astack-mode/scripts/watch-pr/watch-pr.mjs --queued-stack --stack-prs <bottom-to-top>` under `/goal` or a background `invoke_subagent` watcher until `COMPLETE` at the ceiling. Investigate any stall before mutating branches.
6. **Stop at the ceiling.** Extending the run takes new verdicts, so it is a new pass through step 1.

**Reply:** the verified run and its ceiling, each PR's verdict and who produced it, what landed and how you confirmed it, and what the next gap needs.
